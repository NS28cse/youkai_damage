# 実現性検証（合成データ）

実施: 2026-10-30。実際のゲーム映像がまだないため、**合成データ**で「仕組みとして成り立つか」を確かめた。

## 何を確かめたか / 確かめていないか

| 確かめたこと | 方法 |
|---|---|
| 3DS 上画面をカメラで撮った解像度で、数字を検出して読めるか | 合成データで学習・評価 |
| 数字の大きさ（ネイティブ画素の高さ）で精度がどう変わるか | 高さ別に集計 |
| 色でダメージ／回復を分けられるか | 検出モデルの2クラス分類 |
| Colab CLI で学習を回せるか | 実際に T4 で実行 |
| スマホのブラウザでどれだけ速く動くか | 速度テストページ（`bench/`）をオーナーの Android で実行 |

**確かめていないこと**（実映像が必要）: 実際のゲームのフォント・エフェクト・背景での精度、敵／味方を1枚で判別できるか（Q4）、実際の LCD・カメラの見え方。

## 合成データ（`gen_synth.py`）

- 3DS 上画面（400×240）を模した画像に、ランダムな背景（図形・グラデーション）、紛らわしいもの（オレンジ／緑の丸、白い無関係な数字）、0〜4個の数字を描く。
- 数字: 値 1〜9999、オレンジ（ダメージ）か緑（回復）、縁取りあり、半透明（出現・消滅中）あり。高さ 8〜14 ネイティブ画素。フォントは DejaVu Sans Bold（**ゲームのフォントではない**）。
- カメラの再現: LCD の画素格子、画面が映像の高さの 80〜98% を占める配置、斜め（四隅 ±2%）、ぼけ、手ぶれ、色・明るさ・ガンマのずれ、映り込み、ノイズ、JPEG 圧縮。720p（1280×720）で出力。
- 枚数: 学習 3000 / 検証 400 / テスト 400。

## モデルと評価（`train_eval.py`）

- 検出: YOLO11n、入力 640、2クラス（damage / heal）、30エポック。
- 読み取り: 検出枠を切り抜き、YOLO11n（入力 192）で各桁（0〜9）を検出して左から並べる。
- 通し評価: テスト画像で「位置（IoU≥0.5）・種類・値」がすべて合ったものを正解とする。
- 左右反転の水増しは数字の形を壊すので無効にした。

## 再現方法

```bash
python gen_synth.py --out /content/synth --font DejaVuSans-Bold.ttf
EPOCHS=30 python train_eval.py /content/synth /content/out
bench/build.sh /content/out <出力先>   # 速度テストページの組み立て
```

Colab CLI での実行手順は [docs/dev_environment.md](../../docs/dev_environment.md) を参照。
