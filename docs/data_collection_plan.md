# データ収集計画

作成: 2026-10-29（Claude 提案、[decisions.md](decisions.md) の P10）
状態: 提案。試験収集（フェーズ1）の結果を見て更新する。

## 必要なデータは3種類

| データ | 用途 | 中身 | 集め方 |
|---|---|---|---|
| **A. 検出用** | 数字の位置と4種類の判別（YOLO） | カメラで撮ったフレーム + 数字を囲む枠と種類のラベル | 実際に撮影して手作業でラベル付け |
| **B. 文字認識用** | 数値を読む（CRNN） | 数字部分の切り抜き画像 + 値（例 `1234`） | ほぼ自動生成 + 実画像を少し |
| **C. 評価用** | 最終的な CSV が正しいかを測る | 連続した短い動画 + 「いつ・どの種類・いくつ」の正解記録 | 撮影して手で記録。**学習には一切使わない** |

C は重複除外の正しさを確かめる唯一の手段なので、必ず用意する。

---

## フェーズ0: 撮影環境を固める（1〜2日）

学習データは本番と同じ条件で撮ることが大前提。

- **固定**: 三脚で画面の真正面・平行に置く。毎回同じ位置になるよう床や机に印を付ける。
- **光**: 部屋を暗くし、画面への映り込みをなくす。
- **カメラ設定**（最重要）:
  - 露出とピントを固定する（画面長押しで AE/AF ロック）。自動露出のままだとエフェクトが光るたびに明るさが変わる。
  - HDR・美肌などの補正・手ぶれ補正はオフ。
  - 解像度は 1080p か 720p、30fps（60fps は不要）。
- **記録**: 撮影のたびに `sessions.csv` に1行残す（下記）。
- **注意**: カメラアプリの映像とブラウザ（`getUserMedia`）の映像は画質処理が少し違う。評価用データ C にはブラウザで取った映像も必ず含める。

## フェーズ1: 試験収集と実現性の確認（1週目）★ここで設計が決まる

30〜60分ぶん**普通の動画で**撮影し、200〜300枚だけラベルを付けて次を確認する。

| 確認すること | 判断の基準 | 駄目だった場合 |
|---|---|---|
| 1枚の画像だけで**人間が**敵か味方かを当てられるか（Q4） | 9割以上 | 1枚での判別をやめ、数フレームの情報を使う設計に変える |
| 撮影映像の中で数字の高さが何ピクセルか（Q7） | 20px 以上 | カメラを近づける、ズーム、ゲームの表示設定を変える |
| 数字が何フレーム画面に残るか（Q7） | 実測 | 重複除外の設定値に使う |
| 同時に出る数字の最大個数、重なり方 | 実測 | ラベル付けルールに反映 |
| 4種類それぞれの出現比率 | 実測 | 少ない種類は狙って追加収集 |

## フェーズ2: 本収集（2〜3週目）

**量の目安**

- 最初のモデル用: 各種類 300〜500 個の数字（画像 500〜1000 枚程度）
- 最終目標: 各種類 1500 枚以上（Ultralytics の目安）。すべて手作業で付ける必要はない（フェーズ3）。

**多様性を表で管理する**

| 項目 | 変えるもの |
|---|---|
| 場面 | ステージ・マップ、ボス戦と通常戦 |
| キャラ | 編成、敵の種類、スキルのエフェクト |
| 数値 | 桁数（1桁〜最大桁）、クリティカルなど表示が変わるもの |
| 撮影 | 日・時間帯を変える、三脚を置き直す |
| まぎらわしいもの | 数字が出ていない場面、HP・お金・タイマーなど関係ない数字、オレンジや緑のエフェクト（全体の約1割） |

- **少ない種類は狙って撮る**（例: 味方の回復は回復役を多めにした編成で）。
- **容量対策**: 720p で1分あたり 5〜10MB 程度。撮影ごとに Google Drive か PC に移し、スマホからは削除する。
- **フレームの選び方**: 0.5〜1秒に1枚に間引き、画像の類似度（perceptual hash）でほぼ同じものを除き、数字が出ているフレームを優先する。数字は 0.5〜1 秒しか出ないので、間引きは**1秒に2枚以上**を基本とする。

### 低フレームで撮る・間引く方法

| 方法 | 内容 | 向いている用途 |
|---|---|---|
| 普通に撮って後で間引く | `ffmpeg -i session01.mp4 -vf fps=2 -q:v 2 frames/session01_%06d.jpg`（1秒に2枚） | 試験収集・評価用。元動画が残るので取り直しができる |
| タイムラプス | iPhone は間隔を選べず、長く撮るほど間隔が広がる。Android は機種により速度を選べる | 手軽だが、補正がかかりやすいので要確認 |
| インターバル撮影アプリ | Android の Open Camera（無料・オープンソース）の連続撮影機能。露出・ピント固定などの手動設定も可能 | 本収集 |
| 収集用 Web ページ（P11） | ブラウザで一定間隔に静止画を保存。本番と同じ映像経路 | **本収集（推奨）** |

## フェーズ3: ラベル付け（並行して進める）

- **ツール**: CVAT か Label Studio（無料・手元で動く）。Roboflow の無料プランはデータが公開されるので注意。
- **ラベル**: `enemy_damage` / `ally_damage` / `enemy_heal` / `ally_heal`。各枠に「値」も入力する（B の実画像にもなる）。
- **ルールを先に文書化する**（迷う例の画像付き。作成したら `docs/` に置く）:
  - 枠は数字の列全体をぴったり囲む。
  - 消えかけの数字は、人間が読めるなら付ける。
  - 画面の端で切れている数字や、重なっている数字の扱いを決める。
- **半自動化**: 300〜500枚付けたら Colab で最初のモデルを学習し、残りを自動ラベル付け → 人が修正。確信度の低いものから優先して直す。
- **品質確認**: 5〜10%を後日見直す。

## フェーズ4: 文字認識用データ（ほぼ自動）

1. 実映像から 0〜9 の数字画像を、色（オレンジ・緑）や大きさ（クリティカルなど）ごとに切り出す。
2. ランダムな数値に並べて実際の背景に貼り、カメラ特有の劣化（ぼけ・モアレ・傾き・色ずれ・ノイズ）を加える。5万枚程度を自動生成。
3. フェーズ3の実画像の切り抜き（1〜2千枚）は、仕上げの追加学習と精度確認に使う。

## フェーズ5: 評価用データ（1週目に撮って以後は凍結）

- 日を変え、三脚を置き直して、1〜2分の動画を5〜10本撮る。うち数本はブラウザで撮る。
- スロー再生しながら、数字が出るたびに「時刻・種類・値」を記録する。
- 学習には絶対に混ぜない。指標は「記録漏れ」と「余計な記録」の割合。

## データの分け方と管理

- **学習・検証・テストは撮影セッション単位で分ける**（フレーム単位でランダムに分けると、ほぼ同じ画像が両方に入り精度が高く見える）。
- **保存場所**: 画像・動画は Google Drive（Colab から直接読める）。git にはスクリプト・ラベル付けルール・セッション記録のみ。

```
data/
  raw/<session_id>/        動画（Drive）
  frames/<session_id>/     間引いたフレーム
  labels/det/              検出用ラベル（YOLO 形式）
  ocr/real/  ocr/synth/    文字認識用
  eval/                    評価用動画と正解記録（凍結）
  sessions.csv             セッション記録
```

### `sessions.csv` の列（案）

`session_id, date, recorder, phone_model, capture_app, resolution, fps, ae_af_locked, stage, party, notes`
