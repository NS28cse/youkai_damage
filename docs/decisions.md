新しい項目は各表の末尾に追加する。状態は次のいずれか。

- **決定**: ユーザー（プロジェクトオーナー）が決めた、または同意したこと
- **提案**: AI（Gemini / Claude）が提案し、まだ決定されていないこと
- **取り下げ**: 提案したが撤回したこと（理由を残す）

出典の「Gemini①」「Gemini②」は [background.md](background.md) に載せた会話を指す。

## 提案（未決定）

| ID | 日付 | 内容 | 理由 | 提案者 |
|---|---|---|---|---|
| P1 | 2026-10-29 | 推論をスマホのブラウザ内（TF.js / ONNX Runtime Web、小型の YOLO + CRNN）で行う案を最初に試す | サーバー・HTTPS・通信遅延・費用の問題がなくなる。「スマホ単体では性能不足」という前提は未検証 | Claude |
| P2 | 2026-10-29 | **重複除外（フレーム間で数字を追跡し、新しく出た瞬間だけ記録する）を必須機能とする** | 数字は 0.5〜1 秒画面に残るため、追跡しないと1回のダメージが何行も記録される。Gemini① の途中で言及されたが最終まとめから抜けていた | Claude |
| P3 | 2026-10-29 | 「ダメージ／回復」（色でほぼ決まる）と「敵／味方」を別の問題として扱う | 敵／味方の判別が一番難しく未検証。分けたほうが失敗の原因を分析しやすい | Claude |
| P4 | 2026-10-29 | 数値の読み取りに Tesseract を使わず、小型の CRNN を使う | 数字は位置が毎回変わり、色付き・縁取りで背景も派手なため、領域固定の Tesseract 方式（Gemini② の案）は合わない | Claude |
| P5 | 2026-10-29 | 文字認識の学習データは、ゲームの数字画像を切り出して自動生成する | フォントが固定なので、正解付きデータをほぼ無制限に作れる。手作業のラベル付けが減る | Claude |
| P6 | 2026-10-29 | 自己教師あり学習は後回しにし、代わりに疑似ラベル（モデルで自動ラベル付け→人が修正）を使う | 自己教師あり学習は計算資源が大きく、個人開発では割に合わない | Claude |
| P7 | 2026-10-29 | 物体検出は TensorFlow ではなく PyTorch 版 YOLO（Ultralytics）を使う | 資料が多く実装が楽。ONNX / TF.js にも書き出せる | Claude |
| P8 | 2026-10-29 | サーバー技術は未決定（Gemini① は FastAPI、Gemini② は Node.js で食い違い）。初期版はサーバーなし（ブラウザ内保存）でよい | 要件は「表示と CSV 書き出し」なのでデータベースは必須ではない | Claude |
| P9 | 2026-10-29 | リアルタイム推論のサーバーを Render の無料枠に置かない | GPU なし・メモリ 512MB・スリープありで、リアルタイム推論に向かない | Claude |
| P10 | 2026-10-29 | データ収集は [data_collection_plan.md](data_collection_plan.md) の計画で進める | — | Claude |

| P12 | 2026-10 以前 | ファイル命名規則 `[役割]_[対象]_[アーキテクチャ]_[バージョン/日付].拡張子`（例: `detector_4class_yolov8_v1.pt`, `ocr_number_crnn_v1.pt`） | 複数モデルを混乱なく管理するため | Gemini① Turn 13 |
